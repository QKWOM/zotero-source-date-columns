# 论文出处与日期 · 1.6.0

适用于 Zotero 9.0 和 Zotero 10，无需 API 密钥。插件有两项功能：

- **出处与日期**：在条目列表中增加“出处”“日期”两列。先显示 Zotero 中已有的元数据，再依次联网查询 Crossref、arXiv、OpenReview，找到论文的正式发表出处和年月。
- **标记已读**：可以在条目列表或 PDF 阅读器工具栏中把论文标记为已读，已读论文所在的行显示为蓝色调（浅色模式为浅蓝，深色模式为深蓝）。

## 安装

1. Zotero → 工具 → 插件 → 齿轮 → 从文件安装，选择 `xpi/` 文件夹中的 `source-date-columns-1.6.0.xpi`（最新版）。已安装旧版本时直接覆盖安装即可升级。`xpi/` 里也保留了 1.0.0 以来的所有旧版本安装包。
2. 在条目列表标题上右键，勾选“出处”和“日期”（可选勾选“已读”），并拖到合适的位置，例如“创建者”后面。

插件没有自动更新服务。清单中的 `https://source-date-columns.invalid/updates.json` 只是 Zotero 安装校验要求的占位地址，升级需要手动安装新的 XPI。

## 出处与日期

### 使用

- 默认自动查询列表中显示出来的条目（包括参与排序的条目），在后台逐条处理，查到后自动刷新列值。首次查询一个文献库需要一些时间。
- 选中一篇或多篇论文，右键 → **联网刷新出处与日期（所选条目）**：强制重新查询，进度窗口显示完成数、匹配数和失败数。
- 选中一篇论文，右键 → **查看出处查询详情**：显示匹配方式、数据来源、来源链接、日期含义、查询时间、失败原因，以及 arXiv 编号和作者备注。
- 工具菜单 → **关闭自动联网查询出处**：切换为只手动查询。关闭时会清除排队中的自动任务；正在进行的那一条可能继续完成，手动任务不受影响。

PDF 附件和笔记本身不查询，请在带有标题、作者或标识符的文献条目上使用。

### 查询顺序

找到可靠的正式发表记录后即停止，否则按顺序继续：

1. **条目 DOI**：向 Crossref 精确查询。
2. **条目 arXiv 编号**：读取 arXiv 官方 API 的首版上传日期、关联 DOI 和作者备注；有关联 DOI 时再向 Crossref 查询正式记录。
3. **Crossref 标题搜索**：用标题和第一位作者姓氏搜索，校验标题相似度、作者姓氏和年份范围。容许极小的拼写或单复数差异；有多个可信候选时不自动选取。
4. **arXiv 标题搜索**（条目没有 arXiv 编号时）：按标题短语检索 arXiv（优先用冒号后的副标题），校验标题和作者后取得 arXiv 编号、首版上传年月和关联 DOI；有关联 DOI 时再查 Crossref。
5. **arXiv 作者备注**：读取 arXiv 的 `journal_ref` 和作者备注（comment），识别“CoRL 2025”“Accepted to ICRA'26”这类“常见会议缩写 + 年份”写法。支持 CoRL、RSS、ICLR、NeurIPS、ICML、CVPR、ICCV、ECCV、ICRA、IROS、AAAI、IJCAI、ACL、EMNLP、HRI。备注含 workshop、submitted、under review 等字样、同时出现多个会议、或会议年份与上传时间相差过大时不采用。
6. **OpenReview 搜索**：用标题关键词搜索 OpenReview，校验标题和作者。只采用正式录用记录（如“CoRL 2025 Poster”“CVPR 2026”“ICML 2026 regular”，以及 OpenReview 收录的 DBLP 会议记录），跳过 Withdrawn、Rejected、Submitted、Workshop、CoRR 等条目；同一篇论文有多个不同录用出处时不自动选取。

补充规则：

- 只有标题、缺少作者且没有可用标识符时，不自动采用任何标题搜索结果。
- Crossref 只采用 `proceedings-article`（会议论文）和 `journal-article`（期刊论文）。Crossref 未收录、被登记为图书章节，或正式版改名幅度较大的论文可能匹配不到。
- 第 5、6 步的结果只有年份。第 5 步的结果在详情中标注“arXiv 作者备注，未经出版方核实”。

### 显示的出处和日期

| 来源 | 出处 | 日期 |
| --- | --- | --- |
| Crossref 会议论文 | 会议名称，缺失时用论文集标题 | 优先用会议开始年月；缺失时用出版年月，并在详情中注明 |
| Crossref 期刊论文 | 期刊名称 | 优先用印刷出版日期，其次在线出版等其他出版日期 |
| arXiv 作者备注 / OpenReview | 会议全称，如 Conference on Robot Learning (CoRL) | 会议年份 `YYYY` |
| 仅找到 arXiv | arXiv | 官方 `published` 字段的首版上传年月，不是最后修订时间 |
| 本地回退 | Zotero 中的会议名称、论文集标题、期刊名称或预印本平台 | 条目已有的日期；arXiv 条目缺日期时从编号推算年月 |

- 日期格式为 `YYYY-MM`，只有年份时显示 `YYYY`，缺失时留空。
- 正式出处和它的日期始终成对使用，不会用预印本上传时间补到正式发表记录上，也不会用加入文库的时间、Crossref 创建或索引时间当作发表日期。
- Zotero 中已填写了其他出处（例如期刊名）而联网没有找到正式记录时，保留本地信息，不会被“arXiv”覆盖。
- 显示“arXiv”只表示目前各数据源都没有正式发表记录，**不代表论文一定没有发表**。ICLR、CoRL（PMLR）、RSS 等会议不在 Crossref 登记，只能依靠第 5、6 步识别；刚录用、还在审稿，或作者没有更新备注的论文会暂时显示为 arXiv。没查到的条目每天会自动重新查询一次。
- 已知查不到正式出处时，可以在 Zotero 中手动填写该条目的“会议名称”或“期刊”和“日期”，插件会显示你填的信息。

### 数据源说明

- **Crossref、arXiv**：主要数据源，公开接口，无需密钥。
- **OpenReview**：这个接口只要搜索词里带 a、for、with 等常见虚词就会返回“搜索不可用”，所以插件只用标题中的实词去搜。即使这样，它仍会不定时短暂不可用：插件每次最多尝试 3 次；仍不可用时不算查询失败，1 小时后自动重试。
- **未使用的数据源**：DBLP 的 API 目前有人机验证，程序无法调用；Semantic Scholar 不带密钥时经常限流，且许多会议论文只标为 arXiv；Google 学术没有公开接口，自动查询会被验证码拦截。

## 标记已读

### 标记方式

- **条目列表**：选中一篇或多篇论文，右键 → **标记为已读**；所选论文都已读时，这一项变为 **标记为未读**。同时选中已读和未读的论文时，全部标为已读。
- **阅读器工具栏**：打开 PDF 后，工具栏中间标注工具（高亮、下划线……颜色选择）的右侧有 **✓ 已读** 按钮。点击标为已读，按钮呈按下状态、勾变为蓝色实心；再点一次恢复未读。PDF、EPUB、网页快照阅读器都有这个按钮。
- **其他入口**：右键阅读器标签页标题，或使用菜单栏 **工具 → 标记为已读**。

在阅读器中标记的是这份 PDF 所属的论文，不是 PDF 附件本身。条目列表和阅读器按钮的状态互相同步。

### 显示效果

- 已读论文所在行的背景为蓝色调：浅色模式混入 16% 的 Zotero 主题蓝 #4072e5（约 #e0e8fb，浅蓝）；深色模式下背景深，同样比例看不出来，所以提高到 35%（约 #2a3b64，明显的深蓝）。
- 选中的行仍用 Zotero 默认的选中颜色；展开后的 PDF、笔记等子行不变色。
- 可选的“已读”列对已读论文显示 ✓，并可按它排序。
- 行变色依靠本插件的列实现：“出处”“日期”“已读”三列至少显示一列时才生效。

### 存储方式

已读状态保存为普通的 Zotero 标签“已读”，加在论文本身（顶层条目）上：

- 会随 Zotero 同步到其他设备。
- 可以在左下角的标签选择器中筛选已读或未读的论文。
- 手动删除这个标签即恢复未读。

## 缓存、网络与隐私

**发送的数据**：向 `api.crossref.org` 发送论文 DOI，或论文标题和第一位作者姓氏；向 `export.arxiv.org` 发送 arXiv 编号或论文标题；向 `api2.openreview.net` 发送论文标题关键词。不会上传 PDF、笔记、附件或整个文献库。这些服务会收到正常的网络请求信息，例如 IP 地址。

**写入文献库**：出处查询不修改任何文献字段，也不写入文献数据库。只有手动标记已读或未读时，插件才会给论文添加或删除“已读”标签。

**本地缓存**：查询结果保存在 Zotero 配置目录的 `source-date-columns-cache.json` 中，包含检索用的元数据、匹配结果和查询时间，不通过 Zotero 同步。

| 查询结果 | 多久后重新查询 |
| --- | --- |
| 找到正式发表记录 | 7 天 |
| 未找到 / 多个候选 | 1 天 |
| OpenReview 暂不可用 | 1 小时 |
| 网络或服务错误 | 10 分钟 |

- 缓存最多保留 5000 条。条目的标题、作者、标识符等关键信息改变后会重新查询。
- 升级到改变了查询来源的版本时，旧缓存中已找到的结果保留，未找到和失败的记录会重新查询。

**请求方式**：请求逐条串行发送，间隔至少 3.1 秒，单次超时 30 秒。超时、连接中断或 5xx 错误会自动重试一次；遇到服务限流时按服务要求等待。网络失败时保留之前的可靠结果（包括 arXiv 日期），并在详情中标记失败。

**VPN 和代理**：Zotero 使用系统代理设置（或 Zotero 自己的网络设置），不读取终端里的 `HTTP_PROXY` 环境变量。VPN 开启 TUN 模式时，Zotero 的请求可能频繁超时。若查询详情中持续出现超时，请关闭 TUN 模式，或确认 Zotero 能访问 `api.crossref.org`、`export.arxiv.org`、`api2.openreview.net`。

**卸载或禁用**：列、菜单、阅读器按钮和已读行颜色会移除；“已读”标签和本地缓存文件保留。缓存文件可在退出 Zotero 后手动删除。

## 常见问题

- **出处一直是空的或显示 arXiv**：右键 → **查看出处查询详情**，看是否有网络错误；有错误时参考上面的 VPN 说明。没有错误时，说明各数据源都没有正式记录。
- **标记已读后行没有变色**：确认“出处”“日期”“已读”至少有一列是显示的。
- **阅读器里没有已读按钮**：关闭这个 PDF 再重新打开。
- **Zotero 升级后插件被停用（显示“不兼容”）**：`manifest.json` 里的 `strict_max_version` 限定了插件支持的最高 Zotero 版本，目前是 `10.*`。Zotero 升级到下一个大版本（如 11）后，需要先确认下面“开发与验证”里列出的接口仍然可用，再放宽这个值并重新打包。

## 开发与验证

- **文件结构**：
  - `bootstrap.js`：插件生命周期和主窗口加载/卸载钩子。
  - `source-date-columns.js`：三列、右键和工具菜单、已读标签、行样式、阅读器按钮。
  - `online.js`：网络查询、匹配规则、缓存和请求队列。
- **测试**：运行 `node tests/source-date-columns.test.js` 和 `node tests/online.test.js`。
- **打包**：在仓库根目录运行 `zip -X -q xpi/source-date-columns-<版本号>.xpi manifest.json bootstrap.js source-date-columns.js online.js README.md LICENSE`，安装包统一放在 `xpi/` 文件夹。XPI 根目录只包含这 6 个文件。
- **Zotero 接口**：`ItemTreeManager`、`MenuManager` 和 `Zotero.Reader.registerEventListener('renderToolbar')`。最初基于 Zotero 9.0.6 开发；1.6.0 对照 Zotero 10.0.6 的源码逐项核对过插件用到的接口、条目列表的 DOM 结构和阅读器工具栏结构。
- **实现细节**：
  - Zotero 会把插件传入的回调函数再包一层，所以列的 `renderCell` 中拿不到 `this`，要通过 `ZoteroPane.itemsView` 按行号找到条目。
  - 行变色用的是 CSS `:has()`，Zotero 9 和 10 都基于 Firefox 140，支持这个选择器。
  - 已读行的 CSS 规则故意重复了 `.row` 这个 class 来提高 specificity：Zotero 10 的斑马纹规则是 `.row.odd:not(.selected):not(.library-header-row):not(.spacer-row)`，specificity 比 Zotero 9 的高，不提高的话斑马纹行上的已读颜色会被盖住。规则没有用 `!important`，所以 Zotero 自己带 `!important` 的拖拽和高亮颜色仍然优先。
  - 条目列表的行不一定是文献条目：回收站里的 collection、搜索，以及 Zotero 10 的 library header、spacer 行，它们的 `ref` 没有 `isRegularItem()`。三列对这些行一律返回空，不查询、不变色、不能标记已读。
  - 请求间隔用 `setTimeout` 实现，不依赖 `Zotero.Promise`（Zotero 10 中它只是一个 Bluebird 兼容垫片）。
  - `renderToolbar` 只提供工具栏最右侧（搜索按钮左边）的位置，已读按钮是加入后再移到标注工具组 `.toolbar .center.tools` 中的；找不到这个元素时，按钮会留在官方位置。
- **接口文档**：[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[arXiv API](https://info.arxiv.org/help/api/user-manual.html)、[OpenReview API](https://docs.openreview.net/reference/api-v2)。
